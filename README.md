# ModelArk 上手助手：本地试用版

面向业务人员：检查设置 → 第一张产品图 → 用图片生成第一段视频 → 下次使用说明。

这是运行在 Codex 中的 Skill，无需部署服务器或数据库。试点环境为 macOS。安装助手本身不会购买资源、修改账户或执行付费生成。

## 开始试用

将本仓库的 `modelark-onboarding` 文件夹复制到自己的 `~/.codex/skills/` 下（若已有同名技能，先检查并备份，勿直接覆盖），然后新建 Codex 聊天。生成工具及账户认证需要独立配置。

在能发现此 Skill 的 Codex 新聊天中发送：

> 使用 $modelark-onboarding 带我完成首次上手，先检查设置，再做一张产品图和一段视频。

若新聊天暂未发现技能，可以直接提供本地文件：

> 请读取 `<仓库绝对路径>/modelark-onboarding/SKILL.md`，按照这个助手流程带我完成首次上手。

只想预演时加一句：“本次只预演引导，不安装依赖、不修改账户、不提交生成任务。”预演会说明需要的步骤，但不能把模拟结果记作真实完成。

## 业务人员需要做什么

- 说明想做什么，或直接使用陶瓷杯演示。
- 按助手提示完成登录、确有需要的付款或身份验证。
- 查看创作卡和提示词，按生成工具要求确认提交。
- 看第一张图片和第一段视频，阅读保存的 `START-HERE.md`。

助手负责检查资源、准备提示词、调用可用工具、跟踪任务和解释结果。已有资源优先复用；结果未知时先查原任务，避免重复提交。真人能力独立检查，不阻塞无人物的示例。

## 当前验证范围

2026-10-22：已完成 Skill 原型，通过静态格式验证及 7 项离线状态流程测试。测试使用虚拟文件，只验证阶段顺序、恢复和重复提交保护，不代表媒体解码或真实 API 调用验证。

当前会话未加载 Seedream / Seedance 生成工具；现有两个生成 Skill 引用的流程文件也缺失。预检能识别文件缺失；真正生成前仍需修复生成工具接入并验证账户权限。发现 `ve` 命令并不代表已认证或已具备 BytePlus 生成能力。

尚未执行：真实账户认证、模型激活、采购、图片生成、视频生成。不能将此原型视为已经完成端到端验收。

## 文件与维护

- `modelark-onboarding/SKILL.md`：客户引导与阶段规则。
- `modelark-onboarding/references/`：接入、设置和首次创作说明。
- `modelark-onboarding/scripts/preflight.py`：只读本地依赖检查。
- `modelark-onboarding/scripts/session.py`：本地进度与恢复记录，不连接服务端。
- `test_onboarding.py`：离线恢复逻辑测试。

本地记录不保存密钥、签名链接或活体验证 token。每个运行目录只由一个 Agent 操作。已完成的首次体验保持记录，新增创作走普通生成流程。

维护重点是工具接口、模型可用性、账户规则和失败指引。无需常驻服务运维，但仍需明确维护负责人，并在这些依赖变化后回归验证。交付给其他客户前，还需在干净设备上验证安装和真实出图、出视频流程。
