# 完整 Console 开通与首次体验

## 范围及依据

按随包中文指南、英文手册和待确认记录的 v2 执行；下面是 Agent 调度与注册细化，不是重新核验的产品规则。官方规则有变化时记录来源、访问日期和受影响步骤；无法确认则停在对应分支。不要把某一步成功推广到其他权限或渠道。

## 账户注册细分（MA-01）

前提：MA-00 已明确拟使用的组织/账户；没有账户也可先记录拟注册主体，不能以“必须先登录”造成循环阻塞。

1. Agent 检查已有授权登录态，已有正确账户直接复用。没有账户时打开 BytePlus 官方 Console 当前的登录/注册入口；若客户已有有效商务邀请，优先用该邀请。不要自行编造邀请或断言所有客户都需邀请。
2. Agent 根据当前注册页列出必需输入类别，定位注册方式和下一动作。不向客户索取聊天中的密码、验证码、证件或支付信息；用户在官方页面完成敏感输入、验证和条款接受。
3. 遇到邮箱未验证、验证码失效、账户已存在、SSO/管理员限制时，保留具体页面状态，采用页面支持的恢复/登录方式；不要重复注册同一主体或自动更换组织。没有可用邀请则等待明确责任人处理。
4. 注册后 Agent 回查 Console 中实际账户/组织，核对区域和项目，并查客户适用的商务合同。账号能登录不表示 KYC、合同或模型激活已通过。
5. 成功证据：目标账户可访问，组织匹配，适用合同已生效或有权威不适用依据。缺任一项则记录 WAITING_USER / WAITING_EXTERNAL 和恢复条件。成功进入 MA-02，MA-03 可独立推进。

注册表单字段、KYC 材料种类及导航名称以当时官方页面为准，不写死未经核实的地域或证件要求。

## 步骤调度表

每步完整的前提、主体、操作、证据、失败处理和下一步见英文手册同 ID。

| 步骤 | Agent 执行与用户交接 | 等待/完成判定 |
|---|---|---|
| MA-00 | 发现账户候选、区域、项目、旧记录；明确全部目标 | 多候选先选择；无账户登记拟注册目标后 MA-01 |
| MA-01 | 按上方注册细分和合同流程执行 | 会话及适用合同有效；用户完成登录与条款 |
| MA-02 | 先复用激活与额度；需要时准备 Seedance 2.5 USD 具体订单；逐个检查八模型 | 用户付款后回查订单、资格、额度；其余模型受阻逐项保留，不自动加购 |
| MA-03 | 定位企业/组织 KYC，检查材料类别，交用户直接提交 | 未提交等用户；审核中等外部；驳回只提示具体修正；通过才验收，不原样循环提交 |
| MA-04 | 检查 Advanced Creation Rights 档位、实际授权、额度、期限及协议 | 协议授予尚未生效等商务，不用额外付款替代；超出已有授权的付费承诺交用户 |
| MA-05 | 查真人邀请资格及用途，准备官方本人授权/活体路径 | 本人操作后查服务端结果及对应组；企业 KYC 不能代替，虚拟组不能绕过 |
| MA-06 | 复用凭据；分别核实推理 API Key 与管理 API 签名权限；检查同项目 Endpoint | 新权限交接；账户/区域/项目必须匹配；默认保留过滤，Q05 不明时不变更 |
| MA-07 | 用实际工具和当前规范做本地配置与只读连通检查 | 官方 API/Console 可用即不必强制 CLI；CLI 安装不代表 BytePlus 权限正常 |
| MA-08 | 首张图片、基础 API 视频及 Playground 独立验证 | 对应渠道各有可验证结果；基础成功可先交付，不能终止高级分支 |
| MA-09 | 虚拟与真人分支分别检查权利、组、项目和重复素材，再上传 | 真人使用验证返回组；上传目的地未授权则等用户；不得公开私有桶 |
| MA-10 | 用保存的 asset ID 查询处理审核 | Active 才继续；Failed 记录原因；超时保存等待，不重复上传 |
| MA-11 | 各做一个虚拟及已授权真人参考生成测试 | 各自成功且结果可播放，保留素材与任务对应关系 |
| MA-12 | 交付全部能力、八模型状态、文件、费用、责任人与恢复条件 | 每项证据满足才称完整完成；任何必需项等待均为部分完成 |

## 初次图片与视频（MA-08 扩展）

三份基线手册以视频为主，本 Skill 另外保留用户要求的首次 Seedream 图片测试。读 first-creation.md，使用经实际工具确认的 Seedream 4.5、单张 2K 配置；用该图做 Seedance 2.5 视频。图片不要求带真人，不因此绕过或取消 MA-05/MA-11。

若图片转视频的 API 调用满足手册基础 API 验收，复用该任务，不额外重复文字转视频。若走 MCP/CLI，必须有可确认的 BytePlus API 任务与配置证据才能计作 basic_api；单有成功媒体不证明 API 通道。Playground 的验证不能由 API 结果代替。虚拟与真人参考是独立场景；可复用的既有结果须与当前配置、权限和验收要求匹配。

各场景默认一次必要测试，不为八个模型各发付费请求。不新增预算/次数/续费问卷；具体工具的费用确认仍遵守。余额不足、价格异常、未知写入结果均暂停对应动作。

## 状态与恢复

完整记录使用模板中的 MA 步骤、八模型和能力状态：NOT_STARTED、READY、RUNNING、WAITING_USER、WAITING_EXTERNAL、BLOCKED、FAILED、VERIFIED、REUSED。REUSED 也须有当前复核证据。

每次写入追加 attempt（场景、计划、开始时间、请求指纹、资源/任务 ID、状态、下一动作）；不覆盖旧尝试。提交结果不明时保持 RUNNING 并设置 outcome_unknown=true、恢复条件为服务端核对，禁止因无 ID 就重发。素材每 10 秒查询、单次工作最多 10 分钟；视频每 10 秒查询、最多 20 分钟。只读瞬时失败最多重试 3 次，遵守 Retry-After。截止后步骤保存 WAITING_EXTERNAL，attempt 保留 RUNNING 与原 ID；不取消或重建，下次先查询，不能因步骤处于等待就新建尝试。KYC/商务等待不使用高频轮询；仅用户继续时回查，后续自动检查需另有明确调度请求。

每个等待项记录责任角色、下一动作及可观察的恢复条件，不必收集个人联系方式。无真实授权素材时记录 WAITING_USER，不编造真人或授权。报告不得含凭据、证件、活体、认证 token 或签名私有 URL。

## 交付与完成门槛

run-state.json、report.md、首次图片及各场景视频、START-HERE.md。后者解释图片→视频、提示词/参考图的作用、异步等待、成本与后续可用请求；不默认给客户 API 教程。

全部完成必须满足：MA-00–MA-11 已验证或有效复用；八模型均有可用证据；first_image、basic_api、playground、virtual_reference、real_person_reference 各自通过；MA-12 报告与使用说明已交付。模型或能力受限可继续其他分支，但不能以“first_image/video 成功”给全局完成盖章。客户明确缩减范围时记录原范围、新范围和决定时间，再按该范围判断，不删掉历史未完成项。

旧版 onboarding-state.json 是首次体验记录，保留即可；没有 MA/KYC/高级能力字段不等于这些检查已通过。不得删除旧结果或重新生成来完成记录迁移。
